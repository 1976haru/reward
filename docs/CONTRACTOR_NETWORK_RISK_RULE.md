# 계약업체 연관성 탐지 룰 가이드

## 1. 문서 목적
- 보조사업 수급단체와 나라장터 또는 공개 계약자료의 계약업체용역업체가 반복 연결되는 검토 후보를 찾기 위한 룰을 정의한다.
- 본 룰은 위법 여부를 판단하지 않으며, 계약업체 연관성 후보, 반복 연결 검토 후보, 추가 확인 필요 후보를 만드는 보조 도구이다.
- 공개자료 중심 분석 원칙, 개인정보 최소수집 원칙, 중립 표현 원칙을 따른다.

## 2. 탐지 대상
- 특정 수급단체가 같은 계약업체 또는 용역업체와 반복 연결되는 사례
- 동일 계약업체가 여러 보조사업 또는 여러 수급단체에 반복 등장하는 사례
- 유사 사업명과 유사 계약명이 같은 업체와 반복 연결되는 사례
- 같은 연도 또는 인접 연도에 같은 수급단체계약업체 조합이 반복되는 사례
- 계약금액이 유사한 반복 계약 후보
- 계약일자와 기관명 신호가 반복 연결과 함께 나타나는 후보
- 같은 주소 키 또는 같은 지역 키에서 수급단체와 계약업체가 반복 연결되는 사례
- 단, 이 모든 결과는 검토 후보이며 담합, 유착, 위법, 부정수급 판단이 아니다.

## 3. 사용 신호
| 신호 | 설명 | 점수 예시 | 주의사항 |
|---|---|---:|---|
| recipientVendorPairRepeated | 같은 수급단체계약업체 조합 반복 | +30 | 장기계약 가능성 |
| vendorRepeatedAcrossProjects | 같은 계약업체가 여러 사업에 반복 등장 | +20 | 전문업체 가능성 |
| vendorRepeatedAcrossRecipients | 같은 계약업체가 여러 수급단체와 반복 연결 | +20 | 지역 공급망 가능성 |
| projectContractTitleSimilar | 보조사업명과 계약명이 유사 | +15 | 명칭 유사만으로 단정 금지 |
| sameOrAdjacentFiscalYear | 같은 연도 또는 인접 연도 반복 | +10 | 정상 연속사업 가능성 |
| similarContractAmount | 계약금액이 유사 | +10 | 정액계약 가능성 |
| addressKeyRelated | 수급단체 주소 키와 계약업체 주소 키 또는 지역 키 관련 | +10 | 주소만으로 단정 금지 |
| orderingAgencyRepeated | 같은 발주기관 또는 수요기관 반복 | +10 | 기관 특성 가능성 |
| evidenceUrlPresent | 원문 URL 또는 증거 URL 존재 | +5 | 사실관계 점검 필요 |
| businessNumberHashMatch | 사업자번호 해시 일치 | +25 | 원문 저장 금지, 사람 검토 필요 |
| corporateNumberHashMatch | 법인번호 해시 일치 | +25 | 원문 저장 금지, 사람 검토 필요 |

## 4. 점수 기준
| riskScore | 등급 | 의미 | 처리 |
|---:|---|---|---|
| 80~100 | high | 계약업체 연관성 검토 우선순위 높음 | 사람 검토 필요 |
| 60~79 | medium | 추가 확인 필요 | 계약정산 근거 보강 |
| 40~59 | low | 약한 반복 연결 후보 | 보조 검토 |
| 0~39 | minimal | 후보 제외 또는 낮은 우선순위 | 저장 선택 |

## 5. 네트워크 후보 산출 기준
- 수급단체 노드와 계약업체 노드를 구성한다.
- edge는 보조사업 레코드와 계약 레코드의 연결 후보를 의미한다.
- recipientVendorPairKey로 같은 수급단체계약업체 조합을 그룹화한다.
- vendorKey로 특정 업체가 여러 사업 또는 여러 수급단체와 반복 연결되는지 계산한다.
- riskScore 내림차순으로 정렬한다.
- 기본 TOP 50 후보를 반환한다.
- 결과는 업체-사업 반복 네트워크 후보 또는 계약업체 연관성 후보로 표현하며 확정 판단이 아니다.

## 6. 증거와 사유 구성
결과에는 다음을 포함한다.
- candidateId
- networkKey
- recipientKey
- contractorKey
- involvedRecordIds
- involvedContractIds
- riskScore
- riskLevel
- networkSignals
- evidence
- reason
- cautionNotes
- reviewRequired
- createdAt

reason 문구는 다음처럼 중립적으로 작성한다.
- 같은 수급단체와 계약업체 조합이 반복되어 계약정산 근거 확인이 필요합니다.
- 특정 계약업체가 여러 보조사업과 반복 연결되어 추가 확인이 필요합니다.
- 보조사업명과 계약명이 유사하여 연관성 검토 후보로 분류되었습니다.
- 장기계약전문용역지역 공급망 등 합리적 사유 가능성을 함께 검토해야 합니다.

## 7. 개인정보식별정보 제한
- 사업자등록번호와 법인등록번호 원문은 저장하지 않는다.
- 해시 또는 마스킹된 식별자만 사용할 수 있다.
- 대표자명, 전화번호, 상세주소는 단독 기준으로 사용하지 않는다.
- 개인사업자 정보는 개인정보 위험이 높으므로 원칙적으로 제외하거나 마스킹한다.
- evidence와 reason에 개인정보 원문을 넣지 않는다.
- 로그인 필요 자료, 비공개 자료, 내부자료는 탐지 근거로 사용하지 않는다.
- 비공개자료와 로그인 필요 자료는 공개자료 중심 분석 원칙에 맞지 않으므로 제외한다.
- AI 프롬프트에는 원문 식별번호나 개인정보를 넣지 않는다.

## 8. 합리적 사유 가능성
- 같은 업체가 반복 등장해도 전문 용역업체일 수 있다.
- 장기 유지보수 계약, 정기 용역, 지역 공급망, 단가계약, 조달계약 구조상 정상일 수 있다.
- 같은 발주기관의 계약이 반복되는 것은 기관 특성일 수 있다.
- 따라서 후보는 반드시 사람 검토와 원문 확인이 필요하다.

## 9. 검증 기준
- fixture 데이터 1,000건 이상에서 계약업체 연관성 후보를 산출한다.
- 의도적으로 심은 수급단체계약업체 반복 연결 그룹이 high 또는 medium으로 탐지되어야 한다.
- 같은 업체가 여러 사업에 반복 등장하는 후보가 탐지되어야 한다.
- 무관한 계약 연결은 낮은 점수 또는 후보 제외되어야 한다.
- reason에 단정 표현이 없어야 한다.
- reviewRequired는 항상 true여야 한다.
