# 반복 수급 탐지 룰 가이드 (체크리스트 17)

## 1. 문서 목적

- 보조사업 데이터에서 동일 또는 유사 기관·주소·사업명이 반복 등장하는 검토 후보를 찾기 위한 룰을 정의한다.
- 본 룰은 위법 여부를 판단하지 않으며, **"반복 수급 후보"**와 **"검토 필요 후보"**를 만드는 보조 도구이다.
- 공개자료 중심 분석 원칙, 개인정보 최소수집 원칙, 중립 표현 원칙을 따른다.

관련 코드:

- 룰 모듈: [`src/rules/repeatSubsidyRiskRule.ts`](../src/rules/repeatSubsidyRiskRule.ts)
- 표준 타입: [`src/types/repeatSubsidyRisk.ts`](../src/types/repeatSubsidyRisk.ts)
- CLI: [`scripts/run-repeat-risk-rule.ts`](../scripts/run-repeat-risk-rule.ts)
- 테스트: [`tests/repeatSubsidyRiskRule.test.ts`](../tests/repeatSubsidyRiskRule.test.ts)
- 정책 검사: [`scripts/check-repeat-risk-policy.js`](../scripts/check-repeat-risk-policy.js)

## 2. 탐지 대상

- 동일 기관명 또는 유사 기관명으로 여러 보조사업을 받은 사례
- 동일 주소 또는 유사 주소에서 여러 단체가 반복 수급한 사례
- 동일 기관이 유사 사업명으로 반복 신청한 사례
- 같은 연도 또는 인접 연도에 유사 사업을 반복 수행한 사례
- 보조금액이 비슷한 유사 사업 반복 사례
- 단, 이 모든 결과는 검토 후보이며 부정수급 판단이 아니다.

## 3. 사용 신호

| 신호 | 설명 | 점수 예시 | 주의사항 |
|---|---|---:|---|
| normalizedRecipientName 일치 | 기관명 정규화 키가 같음 | +30 | 동일 기관 확정 아님 |
| 기관명 유사도 높음 | entityNameNormalizer 결과 likely 이상 | +20 | 사람 검토 필요 |
| normalizedAddressKey 일치 | 주소 정규화 키가 같음 | +25 | 공유오피스·공공시설 가능성 |
| addressRegionKey 일치 | 지역 주소 키가 같음 | +10 | 단독 기준 사용 금지 |
| projectNameSimilarity >= 0.85 | 유사 사업명 후보 | +20 | 반복 신청 검토 후보 |
| fiscalYear 동일 | 같은 회계연도 | +10 | 단독 기준 사용 금지 |
| fiscalYear 인접 | 전후 1년 이내 | +5 | 단독 기준 사용 금지 |
| subsidyAmount 유사 | 금액 차이 10% 이내 | +10 | 금액 단위 확인 필요 |
| evidenceUrl/sourceUrl 존재 | 원문 근거 존재 | +5 | 사실관계 점검 필요 |
| 대표자명/전화번호 보조 신호 | 마스킹·해시된 값이 보조적으로 유사 | 최대 +5 | 단독 기준 금지 |

## 4. 점수 기준

| riskScore | 등급 | 의미 | 처리 |
|---:|---|---|---|
| 80~100 | high | 반복 수급 검토 우선순위 높음 | 사람 검토 필요 |
| 60~79 | medium | 추가 확인 필요 | 증거 보강 |
| 40~59 | low | 약한 반복 패턴 후보 | 보조 검토 |
| 0~39 | minimal | 후보 제외 또는 낮은 우선순위 | 저장 선택 |

## 5. TOP 50 산출 기준

- riskScore 내림차순으로 정렬한다.
- 같은 기관·같은 주소·같은 사업명 후보가 과도하게 중복되면 groupKey로 묶는다.
- 동일 groupKey 안에서는 가장 높은 점수 후보를 대표로 둔다.
- 최대 50건을 반환한다.
- 결과는 "반복 수급 후보 TOP 50"으로 표현하며 확정 판단이 아니다.

## 6. 증거와 사유 구성

결과에는 다음을 포함한다.

- candidateId
- involvedRecordIds
- riskScore
- riskLevel
- groupKey
- matchedSignals
- evidence
- reason
- reviewRequired
- createdAt

reason 문구는 다음처럼 중립적으로 작성한다.

- "동일 기관명 키와 유사 사업명이 반복되어 검토가 필요합니다."
- "동일 주소 후보에서 여러 보조사업 레코드가 확인되어 추가 확인이 필요합니다."
- "금액과 연도가 유사하므로 반복 신청 검토 후보로 분류되었습니다."

## 7. 개인정보 제한

- 대표자명과 전화번호는 단독 기준으로 사용하지 않는다.
- 원문 전화번호, 주민번호, 계좌번호, 개인 이메일은 저장하지 않는다.
- 상세주소는 normalizedAddressKey 또는 addressRegionKey로 축약된 값만 사용한다.
- evidence와 reason에 개인정보 원문을 넣지 않는다.
- AI 프롬프트에는 원문 개인정보를 넣지 않는다.

## 8. 한계

- 동일 주소는 공유공간, 공공시설, 복지관, 회관, 행정복지센터일 수 있다.
- 같은 기관이 여러 보조사업을 수행하는 것은 정상일 수 있다.
- 유사 사업명은 사업 분야가 같다는 의미일 수 있으며 부정 의심을 확정하지 않는다.
- 룰 결과는 사실관계 점검과 사람 검토가 필요하다.

## 9. 검증 기준

- fixture 데이터 1,000건 이상에서 TOP 50 후보를 산출한다.
- 반복 패턴이 심어진 fixture 그룹이 high 또는 medium으로 탐지되어야 한다.
- 무관한 레코드는 낮은 점수 또는 후보 제외되어야 한다.
- reason에 단정 표현이 없어야 한다.
- reviewRequired는 항상 true여야 한다.

## 10. 후속 작업

- 실제 실데이터 1,000건 기준선에 적용
- 사람 검토 UI와 연결
- 증거 패키지 생성기와 연결
- 사실관계 점검표와 연결
- 리스크 스코어 가중치 튜닝
- 동일 기관·주소·사업명 후보 그룹 시각화
- 신고서 초안 생성 전 승인 게이트 연결

---

본 가이드는 반복 수급 검토 후보를 찾기 위한 보조 기준이며, 위법 여부를 판단하지 않는다. 반복 수급/부정수급을 확정하지 않으며, 모든 후보는 사람 검토 대상이다. 대표자명·전화번호·상세주소는 단독 기준으로 사용하지 않고, 개인정보 원문은 저장·노출하지 않는다.
