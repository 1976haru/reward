# 기관명·단체명 정규화 가이드 (체크리스트 13)

## 1. 문서 목적

- 보조금 자료, 지자체 공고, 업로드 파일, 나라장터 계약자료에서 기관명·단체명 표기 차이를 통합하기 위한 기준을 정의한다.
- 본 모듈은 동일 기관을 **확정**하는 도구가 아니라 **"동일 기관 후보"**를 만드는 정규화·병합 보조 도구이다.
- 공개자료 중심 분석 원칙과 개인정보 최소수집 원칙을 따른다.

관련 코드:

- 표준 타입: [`src/types/entityNormalization.ts`](../src/types/entityNormalization.ts)

## 2. 정규화 대상

- 보조사업자명
- 수급기관명
- 수행기관명
- 단체명
- 법인명
- 계약상대자명
- 발주기관명
- 담당부서명은 기관명과 분리하여 보조 필드로만 사용한다.

## 5. 동일 기관 후보 판정 기준

| 판정 | 조건 | 처리 |
|---|---|---|
| strong_match | 정규화명 완전 일치 | 자동 병합 후보 (단, 확정 아님 — 사람 검토 필요) |
| likely_match | 정규화명 유사도 높음 + 지역/기관 유형 보조 신호 일치 | 사람 검토 후보 |
| possible_match | 일부 단어 유사 또는 약칭 유사 | 추가 검토 필요(보조 검토 후보) |
| no_match | 핵심 토큰 불일치 | 병합하지 않음 |
| ambiguous | 너무 짧거나 일반명사만 남음 | 사람 검토 필요 |

## 6. 유사도 기준

- exact normalized match(`compactName` 완전 일치)는 가장 높은 신뢰도이다.
- token similarity, character n-gram(bigram) similarity, edit distance 기반 점수를 조합해 0~1로 사용한다.
- 너무 짧은 이름, 일반명사, 지역명만 남은 이름은 ambiguous 처리한다.
- 대표자명·전화번호·상세주소는 단독 기준으로 사용하지 않는다.
- 결과는 "동일 기관 후보"이며 확정 판단은 사람이 한다.

## 7. 개인정보·식별정보 제한

- 대표자명은 정규화 키로 사용하지 않는다.
- 전화번호는 단독 병합 기준으로 사용하지 않는다.
- 상세주소는 저장하지 않고 시군구 수준만 보조 신호로 사용할 수 있다.
- 주민번호, 계좌번호, 개인 연락처, 개인 이메일은 수집·저장하지 않는다.
- AI 프롬프트에 원문 개인정보를 넣지 않는다.

## 8. 정확도 검증 기준

- 테스트 데이터는 가짜 기관명으로 구성한다.
- 동일 기관 표기 변형 20쌍 이상을 만든다.
- 다른 기관 쌍 10쌍 이상을 만든다.
- 동일 기관 표기 변형의 80% 이상이 strong_match 또는 likely_match로 분류되어야 한다.
- 다른 기관 쌍은 no_match 또는 ambiguous로 분류되어야 한다.

## 9. 후속 작업

- 실제 경기도/지자체 샘플 데이터로 정규화 품질 검증
- 기관명 사전 보강
- 지역명·지부명 보존/제거 옵션 분리
- G2B 계약데이터 매핑과 재사용
- 업로드 parser 결과에 정규화 필드 연결
- 사람 검토 UI에서 병합 후보 표시

---

본 가이드는 기관명·단체명 표기 통합을 위한 보조 기준이며, 동일 기관을 확정하지 않는다. 자동 확정 병합을 수행하지 않으며, 모든 병합 후보는 사람 검토 대상이다. 본 모듈은 단체를 부정수급자로 단정하지 않고, 보상금 지급을 보장하지 않는다.
